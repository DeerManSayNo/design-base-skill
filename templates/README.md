# 项目设计系统初始化模板

本目录是 foundation 的落地模板，不是本套组自身的项目设计资产，也不注册为 Skill。

## 简短记录原则

每个系统用一句用途、少量当前规则、Token 与实现入口表达，存在例外时补充一小段。必要交互不可省略；公共规则用链接引用，具体值留在 Token，API 留在源码，状态用例留在示例。不要为每个系统重复填写依据表、状态矩阵、迁移表和测试报告。

## 统一项目结构

所有项目采用同一模块化结构。入口只放总览、资产索引和当前事项；设计依据、Token 契约与十三类子系统各自独立维护，不合并成一份规范。

```text
docs/
├── design-system.md
└── design-system/
    ├── design-basis.md
    ├── token-contract.md
    └── systems/
        ├── color.md
        ├── button.md
        ├── slider.md
        ├── radius.md
        ├── typography.md
        ├── icons.md
        ├── elevation.md
        ├── motion.md
        ├── transition-loading.md
        ├── interaction.md
        ├── spacing.md
        ├── sizing.md
        └── layout.md
```

初始化建立上述文档。每个子系统写真实规则，或明确待补齐的具体缺口、不适用的原因，不生成只有标题或未替换占位符的空页。稳定的页面与任务模式新增到 `docs/design-system/patterns/` 并登记入口。文件独立不代表一次实现所有组件，也不要求每次读取全部文件。

已有等价模块化结构保留实际路径并在入口映射；单文件规范首次维护时迁移到此结构，更新引用、移除原处重复正文。迁移仅调整组织方式，沿用已确认的设计决定。Token、主题、组件及运行示例保留项目实际来源，不为文档结构转换 Token 格式、复制源码或引入独立工具链。

## 初始化步骤与完成条件

1. 用 [入口模板](project-entry.md) 建立设计入口，记录总览、权威来源、实际资产及十三类覆盖状态；用 [设计依据模板](design-basis.md) 建立独立设计依据。
2. 参照 [Token 契约模板](token-contract.md) 建立独立 Token 契约文档。已有 Token 保持原格式；新项目先选择实际消费方式，需要 JSON 时才参考 [Token 样例](tokens.example.json)。按实际需要分层和拆文件，组件层可暂缺；不生成含占位字符串的 Token 值。
3. 参照 [子系统模板](subsystem.md) 建立十三类独立规则文件，补齐本次需要的规则。下表检查覆盖范围，未设计项在对应文件写清缺口，入口标记状态，已有实现和公共规范直接链接。间距、尺寸和布局须有基础契约，不能整体不适用；声明可用的项须有可定位规则。
4. 在项目 `AGENTS.md` 引用实际设计入口，保留原有内容；避免重复追加。入口为默认路径时可写：`界面、样式和交互任务使用 design-system Skill，先读取 docs/design-system.md，再按任务定位相关规则与资产。`
5. 按任务授权选定方向并实现 Token 消费与必要组件；未决方向保持候选身份，可用代表性页面验证，不将探索值声明为有效规范。
6. 交由 verify 检查引用、Token 解析及本次可用能力；核对规定的独立文档、系统索引与引用是否齐全。分别说明结构、规则可用性与实际验证结果，不以文件存在代表设计完成。

## 子系统覆盖提示

| 文件 / 系统 | 用简短规则或引用覆盖 |
| --- | --- |
| color / 颜色 | 色板；表面、文字、边框、品牌、状态语义；主题；实际对比度配对 |
| button / 按钮 | 操作层级；尺寸；变体；图标位置；加载、禁用、防重复提交；链接与动作区别 |
| slider / 滑动条 | 单值或区间；min/max/step；方向；格式化；标签；键盘、拖动、触摸；受控 API |
| radius / 圆角 | 刻度；语义角色；组件映射；嵌套和胶囊形使用条件 |
| typography / 字体 | 字体来源与授权；回退；排版角色；字号、行高、字重；多语言与缩放 |
| icons / 图标 | 图标库；尺寸；描边；对齐；命名；装饰性与功能性图标；可访问名称 |
| elevation / 阴影 | 层级用途；阴影组成；主题适配；边框替代；与遮挡层级的关系 |
| motion / 动效 | 时长；缓动；位移；使用条件；中断行为；reduced-motion 替代 |
| transition-loading / 过渡与骨架屏 | 进入退出；加载阈值依据；骨架与内容映射；布局稳定性；超时、错误、重试；辅助技术反馈 |
| interaction / 交互行为 | 状态模型；指针、触摸、键盘；焦点进入、移动、恢复；反馈；取消；错误恢复 |
| spacing / 间距 | 基础刻度；组件内边距、元素间隔、分组间隔、页面留白等语义；密度模式；逻辑方向；响应式映射；例外条件 |
| sizing / 尺寸 | 控件尺寸档位；高度与宽度策略；最小和最大约束；视觉尺寸与点击区域；图标容器；固定、内容自适应和流式尺寸；长文案与缩放 |
| layout / 布局 | 页面区域；栅格与列数；内容最大宽度；页边距和列间距引用；断点或容器查询；排列与重排；滚动归属；固定与吸附；溢出和安全区域 |

允许不适用的范围须写明原因；Slider 与 Scrollbar 分开定义。间距决定空间分隔，尺寸决定元素占用与约束，布局决定区域组织和响应式关系；布局的 gutter、页面留白引用间距 Token，控件占用引用尺寸 Token，避免重复维护数值。页面模式等可按相同模板扩展。具体品牌色、字体和控件值由项目决定，模板不默认批准任何视觉主题。
