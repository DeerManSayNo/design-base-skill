# 项目设计参考

## 采用依据

沿用已确定的用户任务、信息关系与视觉方向；需要形成或重选方向时读取 [设计推导](design-reasoning.md)。本参考用于把选定方向落实为规则。规范与实现冲突时，结合设计记录和适用场景识别已确认规则、局部例外或历史偏差，在本次任务范围内处理。

项目自定义选择说明用途与范围；尚待确定的关键选择标明状态。当前规范保留有效规则，历史沿用项目既有追溯机制。

## 视觉与交互

以下为制定项目规则的检查方向，具体采用值与例外保存在项目中。视觉数值由 Token 表达，结构、状态转换和行为由子系统契约表达。

- 字号、行高、字重、间距、组件尺寸和图标成套采用项目选定体系；具体数值由主题维护。
- 间距刻度须有密度、平台或内容依据，已有项目沿用有效约定；字号、描边和流式尺寸遵循各自规则，不预设跨项目步距。
- 色彩使用表面、文字、品牌和状态等语义角色；状态通过文字、图标等可感知信息表达。
- 按钮随文案与字体变化适配，区分可见尺寸和点击区域；页面保障内容完整与操作可达。
- 按当前场景覆盖加载、禁用、选中、焦点、错误等状态。表单失败保留有效输入，反馈说明恢复方式。

引用标准或组件库具体要求时核对官方资料。涉及对比度、操作目标或布局重排时，按适用条件核对 [WCAG 2.2](https://www.w3.org/TR/WCAG22/) 的相关要求，使用实际颜色配对和运行表现验证。

## 系统关系

需要盘点基础覆盖时查阅 [模板中的覆盖提示](../templates/README.md#子系统覆盖提示)，日常制定规则只处理相关项。

动效提供基础参数，过渡与骨架屏规定场景用法，交互行为规定触发条件和状态变化。间距管理空间分隔，尺寸管理元素占用，布局管理区域组织；布局引用间距和尺寸 Token。跨系统引用同一来源。

## 页面模式与记录

对稳定重复的页面与任务记录适用条件、信息和动作层级、区域排列、响应式及关键状态，引用相关布局规则与代表性实现。搜索、筛选、编辑等模式按业务需要沉淀；明确何时适用和何时应换用其他模式，避免只记录外观。重复实现按实际复用价值提取为组合组件。

设计说明保持简短：采用什么关系、依据是什么、适用在哪里、对应哪个 token 或组件。实现细节由源码和运行示例承载。
